## 失败、修复与恢复

| 尝试 | 终态与分类                                                    | 处理                                                                                               |
| ---- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| a01  | failed；冷环境批次准备超过 600 秒；另发现代理上游路径缺 `/v1` | 保留失败证据；使用独立代理修复路径，真实推理探针通过后重跑                                         |
| a02  | failed；基线 0.76662，首轮 train 冷构建再次超过 600 秒        | 将两组配方的批次准备预算改为 1800 秒                                                               |
| a03  | failed；首轮 Memory 的模型请求被代理拒绝 reasoning_effort low | 在实验代理明确允许并透传参数，真实工具及业务编辑探针通过                                           |
| a04  | failed；首次 select 因动态 CPU 编号不同而判断不可比           | 修正 agentbench 条件投影，保留容量、配额、内存和完整原生证据；测试、审查及真实失败输入离线重放通过 |
| a05  | succeeded；第七轮训练另有一次上游模型过载                     | SDK 默认有限补测在清理失败尝试后重做该题，第二次有效；其他有效题未重做，实验未重启                 |

第七轮故障为 `APIConnectionError / NETWORK_FAILURE`，上游报告 server overload，属于暂时性环境故障。安装的 SDK 默认每题最多 3 次尝试、5000ms 退避；本次使用 2 次。两次尝试均确认 cleaned，最终该组仍为 10 题有效评分。未为此改变实验参数或增加另一层重试。

CPU 修复只在已确认 availableCpus 为正整数的 agentbench 质量比较投影中去掉动态核编号；Selector 仍执行严格可比性校验，inferencebench 不变，原生 CPU 证据保留。修复后的 `pnpm check` 已实际通过格式、核心与 Web 类型检查、36 项单元测试及构建；随后本次真实运行完成全部严格选择。

# DSH Harness²

The baseline Bundle starts with an empty prompt and no skills.

For each task, this example starts from a fixed baseline, executes Base once, proposes and evaluates INV and DOM improvements separately, composes a candidate from the baseline and evaluates it, then anonymously compares the final deliveries. The default selects ten distinct WorkBuddy Office tasks; configure the task list and exploration width in recipe.yaml.

At k=1, ten tasks require 40 evaluation runs. The Recipe retains its 4,500-second evaluator task timeout and 72-hour experiment wall budget. Pi uses a 30-minute request timeout and 60-minute execution timeout. Model-call and output-token ceilings are omitted. Benchmark phase limits and model-service defaults may also apply. To request an output-token limit, explicitly configure the Agent or evaluator service; native judging uses the selected service's setting. Declare an evaluator output limit in either the service or solver configuration: the Evaluator SDK rejects duplicate limits.

Prepare Node 24, project dependencies, working [arsi-evaluator](https://github.com/ARSI-LAB/ARSI-Evaluator) and [agentbundle](https://github.com/ARSI-LAB/agentbundle) SDKs, and the Evaluator's WorkBuddy Office execution environment. Set MODEL_NAME, EVALUATOR_MODEL_NAME, MODEL_ENDPOINT, and MODEL_API_KEY in the runtime environment rather than storing their values in the Recipe. The Evaluator initializes the Agent under test; RSI does not preinstall a separate DSH instance. EVALUATOR_MODEL_NAME selects the model for evaluation execution and any native judging that selects the default service; it is required and has no fixed default. MODEL_NAME controls the optimizer Agent separately. The endpoint and credentials are inherited through the existing environment references.

Run `arsi run examples/harness/dsh-harness2/recipe.yaml` from the project root. Run facts, candidates, measurements, and receipts are stored in `.rsi/`. A successful native evaluation exit does not mean the answer is correct. Inspect the Measurement's technical status, coverage, per-task results, and delivery artifacts.

Harness² updates Memory and revises the invariant and domain Proposers' guidance at the end of each task. Set `memory: false` or `reflection: false` in the Recipe to disable a capability. The Reflection configuration sets a 60-minute local timeout. To customize it, select a replacement configuration file using `reflection.configFile`. Accepted guidance becomes available to later calls. Use user-owned guidance paths to retain a revision with `arsi reflection apply <revision-id>`.

Proposers receive one read-only execution file per measurement with every available non-thinking event from each attempt's canonical trace, including phase/status events and complete tool calls. There is no whole-trace middle truncation. Tool-return payloads keep a prefix of 2,000 Unicode characters with explicit omission metadata (a character limit, not an exact model-token count). Read the supplied `supplementaryPath` with line ranges; the inline inventory and final-reply preview do not replace the event sequence. Unavailable source evidence remains explicitly unknown.

Component bindings, Prompts, and the editing Skill use the Harness² Policy's default assembly. The Recipe configures the application, Policy parameters, Agent timeouts and evaluator benchmark/model services. Benchmark-specific evaluator settings belong to the Recipe rather than Policy defaults. agent explicitly binds agent.pi and reads MODEL_NAME, MODEL_ENDPOINT, and MODEL_API_KEY by default. Override the relevant component configuration in the Recipe's bindings when customization is needed.

For proposal audits, each optimizer `agent` call retains `diagnostics.jsonl` under the experiment call directory: completed assistant messages, tool starts/results, validation failures/recovery and terminal errors. For Proposer calls, the receipt links the workspace snapshot containing the actual instructions and authorized input files, and records the validated final response. Link these child calls to the INV/DOM, Composer and Memory parent calls to distinguish generated edits, committed candidate changes and valid no-change results. Benchmark Agent execution traces are retained separately through each Measurement's authorized evidence index.
